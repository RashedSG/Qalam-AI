# قلم | QALAM — دليل التشغيل الأول

من مستودعٍ على GitHub إلى مراسلة صادرة مطبوعة، بالترتيب.

> **ما لا يفعله هذا الدليل:** لا يُنشئ لك مشروع Supabase ولا موقع Netlify.
> هذه حسابات ولوحات تحكم. ما يفعله: يقول لك **ماذا** تفعل بالضبط، **وبأي
> ترتيب**، و**كيف تتحقّق** أنك فعلته صحيحًا.
>
> ⚠️ الترتيب ليس تفصيلًا. خطوتان أدناه (٣ و٤) تعتمدان على أنك سجّلت دخولك
> **قبلهما** — وتنفيذهما قبل ذلك يتركك مديرًا لا يرى مراسلاته السرية ولا
> يستطيع اعتماد شيء.

---

## الخطوة ١ — مشروع Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. **اختر المنطقة بعناية.** المراسلات الحكومية قد تُلزمك بمنطقة بعينها
   (سيادة البيانات)، وتغييرها بعد التشغيل يعني ترحيلًا كاملًا لا إعدادًا.
3. احفظ من **Project Settings → API**:
   - `Project URL`
   - `anon public key`
4. احفظ من **Project Settings → Database → Connection string → URI**:
   - سلسلة الاتصال (تحتوي كلمة مرور القاعدة) — تُستخدم في الخطوات التالية.

```bash
export SUPABASE_DB_URL='postgresql://postgres:…@db.xxxx.supabase.co:5432/postgres'
```

⚠️ هذه السلسلة تفتح القاعدة كاملة. لا تُكتب في ملف داخل المستودع ولا تُرسل في
محادثة.

---

## الخطوة ٢ — تطبيق الهجرات

٢٣ ملفًا، بالترتيب الرقمي. كلها مكتوبة لتُطبَّق مرتين بلا أثر.

```bash
for f in supabase/migrations/*.sql; do
  echo "→ $f"
  psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -f "$f" || break
done
```

> بديل بلا `psql`: الصق كل ملف في **Supabase → SQL Editor** بالترتيب. ٢٣ لصقة —
> ممل لكنه يعمل. لا تخلط الترتيب: الهجرة ٠٠١٠ تعتمد على ٠٠٠٨.

**للتحقق:** يجب أن تكون هناك مؤسسة واحدة وصفر عضويات (لا مستخدمين بعد):

```sql
select (select count(*) from public.organizations) as orgs,
       (select count(*) from public.memberships)  as memberships;
-- المتوقع: orgs = 1, memberships = 0
```

## الخطوة ٣ — سجّل دخولك مرة واحدة

**شغّل التطبيق محليًّا** (أسرع من انتظار النشر) وسجّل دخولك بحسابك:

```bash
cp .env.example .env     # املأ VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
npm install && npm run dev
```

سترى: **«لا تنتمي إلى أي مؤسسة نشطة»**. هذا متوقّع — الخطوة التالية تصلحه.

⚠️ **لماذا هذا الترتيب؟** الهجرة `0009` هي التي تُنشئ العضويات، وهي تعمل على
المستخدمين **الموجودين وقت تنفيذها**. فإن طُبّقت على مشروع فارغ (وهذا ما حدث في
الخطوة ٢) لم تجد أحدًا. ولهذا نسجّل الدخول الآن ثم نعيدها.

## الخطوة ٤ — ربط حسابك بالمؤسسة

### ٤أ) أعد تنفيذ الهجرة ٠٠٠٩

تُنشئ عضويتك وتجعلك مدير المؤسسة (أقدم مستخدم = المدير):

```bash
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 \
  -f supabase/migrations/0009_backfill_organization.sql
```

### ٤ب) أكمل ما لا تفعله ٠٠٠٩

عدّل القيم الأربع في أعلى `scripts/setup/bootstrap.sql` (اسم مؤسستك، ورمزها،
وبريدك)، ثم:

```bash
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -f scripts/setup/bootstrap.sql
```

**ماذا يضيف هذا الملف، ولماذا هو ضروري؟**

| يصلح | لماذا يهم |
|---|---|
| اسم المؤسسة ورمزها | `0009` تضع `مؤسستي` و`DEFAULT`، والرمز يظهر في **كل رقم مراسلة** |
| التخليص الأمني → أعلى تصنيف | `0009` تتركه `1`، فلا ترى مراسلاتك **السرية**. خلل يظهر متأخرًا ويصعب تفسيره |
| أدوار سير العمل | `0009` تمنح `organization_admin` + `employee` فقط — **وهما لا يكفيان لاعتماد مراسلة ولا توقيعها** |

> ⚠️ الملف يسند لك ستة أدوار مجتمعة، وهذا **يُبطل فصل المهام**: تكتب المراسلة
> وتراجعها وتعتمدها وتوقّعها بنفسك. مقبول في تشغيل تجريبي بشخص واحد، **غير
> مقبول في الإنتاج**. بعد إضافة موظفيك اسحب من نفسك `reviewer` و`approver`
> و`signatory` من شاشة «المستخدمون».

**للتحقق:** حدّث التطبيق — يجب أن تظهر أقسام «المراسلة المؤسسية» و«الإدارة».

## الخطوة ٥ — حاوية المرفقات

سياسات الوصول مُطبَّقة في `0014`، لكن الحاوية نفسها إعداد منفصل.

**Supabase → Storage → New bucket:**

| الحقل | القيمة |
|---|---|
| الاسم | `correspondence-attachments` (بالضبط) |
| **Public bucket** | **مُطفأ** — إلزامي |
| File size limit | `25 MB` |

⚠️ حاوية عامة تعني رابطًا دائمًا لأي مستند مؤسسي يعرفه من يعرف المسار، **بلا
فحص صلاحية ولا سجل**.

ثم أعد تنفيذ `0014` لتُطبَّق سياسات Storage (تتخطاها الهجرة بصمت إن لم يكن
المخطط موجودًا):

```bash
psql "$SUPABASE_DB_URL" -f supabase/migrations/0014_attachments.sql
```

قبل هذه الخطوة يعمل كل شيء عدا الرفع والتنزيل.

## الخطوة ٦ — أغلق التسجيل ⚠️

**نفّذ هذا قبل أن يعرف أحدٌ عنوان موقعك.**

```bash
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -f scripts/setup/harden.sql
```

الوضع الافتراضي `public`: **أي شخص يملك الرابط يُنشئ حسابًا في مؤسستك.**
والبوابة في القاعدة لا في الواجهة — إخفاء صفحة التسجيل في React ليس تفويضًا.

لدعوة موظف: ألغِ تعليق القسم الثاني في `harden.sql` وعدّل البريد.

> ⚠️ **فجوة معلومة:** الدعوة تُنشئ **حسابًا** لا **عضوية**. بعد أن يسجّل الشخص
> دخوله، أعد تنفيذ `0009` (تُنشئ عضويته كـ`employee`)، ثم أسند له دوره وتخليصه
> من شاشة «المستخدمون». خطوة يدوية لكل عضو.

## الخطوة ٧ — فعّل الاستعادة الزمنية (PITR)

**Supabase → Database → Backups → Point in Time Recovery.**

بدونه أقصى ما يُستعاد هو نسخة أمس — أي فقدان يوم كامل من المراسلات في أسوأ
الحالات.

⚠️ **وملفات Storage ليست في النسخ الاحتياطي لقاعدة البيانات إطلاقًا.**
الاستعادة تُعيد صفوف المرفقات — الأسماء والأحجام والصلاحيات — **دون الملفات**.
النظام يبدو سليمًا وزرّ التنزيل يفشل. الخيارات في
[`operations.md`](operations.md#الجزء-الثاني--النسخ-الاحتياطي-والتعافي).

## الخطوة ٨ — Netlify

1. **Add new site → Import an existing project** → اختر المستودع والفرع.
2. البناء يُقرأ من `netlify.toml` — لا تغيّره.
3. **Site configuration → Environment variables**، أضف:

| المتغيّر | القيمة | يظهر في المتصفح؟ |
|---|---|---|
| `VITE_SUPABASE_URL` | Project URL | ✅ نعم (عامّ) |
| `VITE_SUPABASE_ANON_KEY` | anon public key | ✅ نعم (عامّ) |
| `SUPABASE_URL` | نفس Project URL | ❌ لا |
| `SUPABASE_ANON_KEY` | نفس anon key | ❌ لا |
| `OPENAI_API_KEY` | مفتاحك من OpenAI | ❌ **لا — أبدًا** |

⚠️ `OPENAI_API_KEY` **لا يبدأ بـ`VITE_`**. كل ما يبدأ بـ`VITE_` يُحزَم في
ملفات المتصفح ويقرأه أي زائر. والمفتاح يُستخدم في دوال Netlify وحدها.

⚠️ `SUPABASE_SERVICE_ROLE_KEY` **غير مطلوب**. لا تضفه. حد المعدّل وتتبّع
الاستخدام يعملان برمز جلسة المستخدم ومفتاح `anon`.

4. بعد النشر: **Supabase → Authentication → URL Configuration** — أضف نطاق
   Netlify إلى `Site URL` و`Redirect URLs`، وإلا فشل الدخول بـGoogle.

## الخطوة ٩ — الفحص قبل البيانات الحقيقية

```bash
psql "$SUPABASE_DB_URL" -f scripts/setup/verify.sql
```

١٣ فحصًا. **كل سطر يجب أن يكون `PASS`.** الفرق بين «نفّذتُ الخطوات» و«النظام
مُهيّأ فعلًا» هو هذا الملف.

```
 ✅ PASS | RLS على كل جدول                       | كل الجداول محمية
 ✅ PASS | لا جدول متاح لـanon                   | لا صلاحية جدول لـanon
 ✅ PASS | anon لا يتجاوز RLS إلا بالتحقق العلني | verify_correspondence وحدها
 ✅ PASS | التسجيل مُغلق (invite_only)            | الوضع الحالي: invite_only
 ✅ PASS | حاوية المرفقات خاصة                   | موجودة وخاصة
 …
```

| سطر | معناه |
|---|---|
| `حاوية المرفقات` = FAIL | الخطوة ٥ ناقصة، أو الحاوية **عامة** — أوقف كل شيء وأصلحها |
| `التسجيل مُغلق` = FAIL | الخطوة ٦ ناقصة. موقعك مفتوح للتسجيل الآن |
| `تخليص المسؤول` = WARN | لن ترى أعلى تصنيف في مؤسستك. أعد الخطوة ٤ب |
| `SKIP` | بيئة اختبار بلا مخطط `storage` — لا يظهر في Supabase حقيقي |

## الخطوة ١٠ — أول مراسلة: من الصفر إلى ورقة مطبوعة

هذا التمرين يثبت أن الدورة كلها تعمل. **نفّذه قبل إدخال أي مراسلة حقيقية.**

1. **اكتب** — `/write`: موضوع ونص، واختر تصنيفًا **سريًّا** (يختبر التخليص).
2. **أرسل للمراجعة** — افتح المراسلة → لوحة سير العمل → «قيد المراجعة».
3. **اعتمد ووقّع** — قيد الاعتماد → معتمدة → أصدر الرقم → وقّع → صادرة.
   - **الرقم يجب أن يحمل رمز مؤسستك** الذي ضبطته في الخطوة ٤ب:
     `MOT/ROOT/OUT/2026/0001`
4. **اطبع** — بطاقة «معاينة الوثيقة» → «طباعة / حفظ PDF».
   - ⚠️ يجب أن تُطبع **الوثيقة وحدها**: لا قوائم ولا أزرار ولا لوحات.
   - وأن يظهر رمز QR في التذييل.
5. **امسح رمز QR بهاتفك.**
   - يجب أن تفتح صفحة التحقق وتعرض **الرقم والتاريخ والجهة — ولا شيء غيرها**.
   - ولا تعرض الموضوع ولا النص ولا الأطراف ولا التصنيف. هذا مقصود: من يحمل
     الورقة يعرفها أصلًا، ومن لا يحملها لا يجوز أن يعرف عنها شيئًا.
6. **افتح الرابط في نافذة خاصة** (بلا تسجيل دخول) — يجب أن يعمل كما هو.

### ثم: تمرين تعافٍ واحد

قبل البيانات الحقيقية، استعد نسخة إلى مشروع Supabase منفصل وشغّل عليها
اختبارات التكامل:

```bash
QALAM_TEST_DATABASE_URL="postgresql://…/restored" npm run test
```

⚠️ وستكتشف عمليًّا ما يقوله [`operations.md`](operations.md): **المرفقات لن
تعود.** اكتشافها الآن خيارٌ، واكتشافها وقت الحاجة كارثة.

## الخطوة ١١ — هوية مؤسستك وإعداداتها

بعد أن يعمل كل ما سبق:

| الشاشة | ماذا تضبط |
|---|---|
| `/organization` | الترويسة والتذييل والشعار المطبوعة على كل وثيقة |
| `/organization/correspondence` | **سمِّ مستويات التصنيف كما تسمّيها مؤسستك**، واضبط صيغة رقم المراسلة |
| `/organization/structure` | هيكلك التنظيمي الحقيقي (الإدارات والوحدات) |
| `/organization/users` | أدوار كل موظف وتخليصه الأمني |

> ⚠️ **الشعار**: مسار على نطاقك (يبدأ بـ`/`) أو `data:image` فقط. سياسة أمن
> المحتوى تحجب الروابط الخارجية — ولأن شعارًا خارجيًا يُبلّغ نطاقًا آخر بكل مرة
> تُفتح فيها وثيقة.
>
> ⚠️ **لا يُقال عن قالب الوثيقة إنه «معتمد»** من أي جهة. إدخال الترويسة لا يعني
> اعتمادها؛ الاعتماد قرار مؤسستك بعد مراجعتها.

**أخطر قرار في النظام كلّه هو `/organization/users`:** من يعتمد؟ من يوقّع؟ من
يرى المؤسسة كاملة؟ وتخفيض رتبة تصنيف يكشف مراسلاتٍ كانت محجوبة — ولذلك تعرض
الشاشة الأثر بالأرقام قبل التنفيذ، ويُسجَّل كل تغيير باسمك.
