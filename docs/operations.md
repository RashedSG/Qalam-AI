## الجزء الأول — المراقبة

### ما يُراقَب

| الإشارة | من أين | ماذا يعني ارتفاعها |
|---|---|---|
| `ai.failed` بحسب `errorCode` | سجل دوال Netlify | مزوّد الذكاء متعثّر، أو المفتاح انتهى |
| `upstream_timeout` | سجل دوال Netlify | `AI_TIMEOUT_MS` أضيق مما يحتاجه النموذج |
| `rate_limited` | سجل دوال Netlify | إمّا إساءة استخدام وإمّا حصّة ضيّقة |
| `ai_requests_metadata.status='error'` | القاعدة | فشلٌ يصل المستخدم فعلًا |
| `agent_runs.status` | القاعدة | تعثّر حلقة الوكيل |
| بطء `search_correspondence` | Supabase → Query Performance | فهرس البحث لم يُبنَ أو تضخّمت البيانات |
| نمو `audit_log` | القاعدة | طبيعي — لكنه يحدّد كلفة النسخ الاحتياطي |

### ⚠️ ما لا يُسجَّل — ولا يجوز أن يُسجَّل

هذا حدٌّ صريح، لا تفصيلًا تقنيًّا:

- **لا نصّ مراسلة، ولا موضوعها، ولا نصّ الرسالة الواردة.**
- **لا نصّ التوجيه (prompt) ولا ردّ النموذج.**
- **لا نصّ منطوق ولا صوت خام.**
- **لا رموز وصول ولا مفاتيح ولا بُنى `Authorization`.**
- **لا بريد إلكتروني.**

`netlify/functions/_shared/log.ts` يُنفّذ ذلك بنيويًّا: نوع `LogEvent` مغلق —
لا يُسجَّل إلا حقلٌ مُعلَن — و`sanitizeValue` تحجب ما يشبه المفاتيح والرموز
والبريد، وتُسقط أي نصّ يتجاوز ٦٤ محرفًا أو يحوي سطرًا جديدًا. **ولا يُقرأ جسم
خطأ المزوّد إطلاقًا**: قد يحمل صدى ما أُرسل إليه. تُصنَّف الحالة ولا يُقرأ
الجسم.

اختبارات ساكنة تفحص هذا الحدّ في كل مرحلة، فلا يُضاف حقل سهوًا.

### خطوات المشغّل — يدوية

> **MANUAL ACTION REQUIRED** — لا يُنفَّذ شيء ممّا يلي من المستودع.

1. **سجلّات الدوال**: Netlify → Site → Logs → Functions. لتمديد الاحتفاظ إلى
   ما بعد المدة الافتراضية يلزم Log Drain (خطة مدفوعة) — وجهته يقرّرها
   المشغّل.
2. **سجلّات القاعدة**: Supabase → Logs & Analytics → Postgres / API.
3. **أداء الاستعلامات**: Supabase → Advisors → Query Performance. راجعها بعد
   أول شهر تشغيل حقيقي: أنماط الاستعلام الفعلية هي التي تُظهر الفهرس الناقص.
4. **مستشار الأمن**: Supabase → Advisors → Security. يجب أن يبقى بلا تحذير
   `RLS disabled` ولا `SECURITY DEFINER view`.
5. **تنبيه على الفشل**: لا تنبيه مُعدّ في المشروع. إن أُريد، يُوصَل Log Drain
   بأداة التنبيه التي تستعملها المؤسسة.

### استعلامات تشغيلية جاهزة

```sql
-- فشل الذكاء في آخر يوم، بحسب رمز الخطأ
select error_code, count(*)
from public.ai_requests_metadata
where status = 'error' and created_at > now() - interval '1 day'
group by 1 order by 2 desc;

-- المراسلات المتأخرة المفتوحة
select count(*) from public.correspondences
where due_at < now() and current_status not in ('issued','closed','archived');

-- حجم الجداول الأسرع نموًّا
select relname, pg_size_pretty(pg_total_relation_size(c.oid)) as size
from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind = 'r'
order by pg_total_relation_size(c.oid) desc limit 10;
```

## الجزء الثاني — النسخ الاحتياطي والتعافي

### ⚠️ ملفات Storage ليست في النسخة الاحتياطية لقاعدة البيانات

**هذا أهم سطر في المستند.**

نسخ Supabase الاحتياطية التلقائية تشمل **قاعدة PostgreSQL فقط**. مرفقات
المراسلات تُخزَّن في Storage (دلو `attachments`)، و**Storage ليس ضمنها**.

ما يعنيه ذلك عمليًّا: استعادةٌ من نسخة القاعدة وحدها تُعيد **صفوف جدول
`attachments`** — الأسماء والأحجام والمسارات والصلاحيات — بينما **الملفات
نفسها لا تعود**. النظام يبدو سليمًا: المرفق مذكور في المراسلة، وزرّ التنزيل
موجود، والضغط عليه يفشل.

هذه ليست علّة في قلم ولا في Supabase؛ هي حدّ المنتج. لكن اكتشافها **وقت
الحاجة** كارثة، فتُذكر هنا صراحةً.

**نسخ Storage احتياطيًّا مسؤولية منفصلة يقرّرها المشغّل.** الخيارات:

- مزامنة دورية للدلو إلى تخزين خارج Supabase (S3 أو ما يماثله) عبر مهمة
  مجدولة تستعمل `service_role` — **من خادم، لا من المتصفح**.
- تفعيل نسخ Storage إن أتاحته خطة المشروع (راجع لوحة المشروع؛ يتغيّر بحسب
  الخطة والمنطقة).
- سياسة مؤسسية: عدم اعتماد Storage مصدرًا وحيدًا للأصل الورقي.

**لا يُقال إن النسخ الاحتياطي كامل ما لم تُنفَّذ إحدى هذه.**

### ما يشمله النسخ التلقائي

| العنصر | مشمول؟ |
|---|---|
| جداول `public` كلها (مراسلات، مرفقات كصفوف، أدوار، سجل تدقيق، تواقيع) | ✅ |
| `auth.users` والجلسات | ✅ (ضمن نسخة المشروع) |
| الدوال والمشغّلات وسياسات RLS | ✅ |
| **ملفات Storage** | ❌ **لا** |
| متغيّرات البيئة في Netlify | ❌ لا — تُوثَّق خارجيًّا |
| أسرار المزوّد (مفتاح OpenAI) | ❌ لا — تُدار عند المزوّد |

### دورية النسخ

| الخطة | التلقائي | الاستعادة الزمنية (PITR) |
|---|---|---|
| Free | لا نسخ مُدارة | لا |
| Pro | يومي، احتفاظ ٧ أيام | إضافة اختيارية مدفوعة |
| Team / Enterprise | يومي، احتفاظ أطول | متاح |

> **MANUAL ACTION REQUIRED** — للتشغيل المؤسسي: فعّل PITR من
> Supabase → Database → Backups. بدونه أقصى ما يُستعاد هو نسخة أمس، أي
> فقدان يوم كامل من المراسلات في أسوأ الحالات.

### نسخة يدوية — قبل كل هجرة كبيرة

```bash
# القاعدة كاملة
pg_dump "$SUPABASE_DB_URL" --no-owner --no-privileges -Fc -f qalam-$(date +%F).dump

# البنية وحدها (للمقارنة والمراجعة)
pg_dump "$SUPABASE_DB_URL" --schema-only --no-owner -f qalam-schema-$(date +%F).sql
```

⚠️ الملفّ الناتج يحوي **كل المراسلات ونصوصها**. يُعامَل معاملة الوثيقة السرية:
تخزين مُعمّى، وصول مقيَّد، وحذف عند انتهاء الحاجة. نسخة احتياطية مهمَلة على
حاسوب شخصي هي أوسع تسريبٍ ممكن للنظام كله.

### إجراء التعافي

1. **أوقف الكتابة.** Netlify → Deploys → Lock، أو أوقف الموقع. استعادةٌ فوق
   نظامٍ يكتب تُنتج بيانات مختلطة.
2. **استعد القاعدة**: Supabase → Database → Backups → Restore، أو
   `pg_restore` من نسخة يدوية.
3. **تحقّق من الهجرات**: طبّق `supabase/migrations/*.sql` بالترتيب على القاعدة
   المستعادة. كلها مكتوبة لتُطبَّق مرتين بلا أثر.
4. **⚠️ استعد ملفات Storage من مصدرها المنفصل.** إن لم يكن موجودًا، فالمرفقات
   مفقودة — وهذا ما يجب إبلاغه للمؤسسة صراحةً، لا اكتشافه لاحقًا.
5. **أعد ضبط متغيّرات البيئة** في Netlify (راجع `.env.example`).
6. **تحقّق قبل الفتح**:

```sql
-- RLS مفعّلة على كل جدول
select relname from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname='public' and c.relkind='r' and not c.relrowsecurity;
-- يجب أن يعود فارغًا

-- سجل التدقيق متصل
select count(*) from public.audit_log;

-- المرفقات: الصفوف موجودة — والملفات؟ يجب فحص عيّنة يدويًّا
select count(*) from public.attachments;
```

7. **افتح الكتابة** بعد نجاح الفحوص لا قبله.

### ما لا يُستعاد بالنسخة

- **الجلسات المفتوحة**: يُطلب من الجميع تسجيل الدخول من جديد. هذا مقصود.
- **عدّادات أرقام المراسلات** تعود إلى حالتها وقت النسخة. إن صدرت مراسلات بعد
  النسخة وقبل العطل، فقد تُصدَر أرقام مكرّرة. **افحص
  `reference_number_counters` قبل فتح الكتابة**، وارفع العدّاد يدويًّا إن لزم.
- **رموز التحقق** المولَّدة بعد النسخة تختفي، فأوراقها المطبوعة لن تُتحقَّق.

## الجزء الثالث — الأداء

### حجم ما يُحمَّل

| الحزمة | مضغوطة | ملاحظة |
|---|---|---|
| `react` | ‎~54 kB | مشتركة، تُخزَّن في ذاكرة المتصفح |
| `supabase` | ‎~59 kB | مشتركة |
| `index` (الغلاف والمسارات) | ‎~69 kB | |
| أثقل صفحة (تفاصيل المراسلة) | ‎~7 kB | |
| مولّد QR + الوثيقة | ‎~3٫4 kB | لا يُحمَّل إلا عند فتح وثيقة أو صفحة الهوية |

كل صفحة `lazy` بذاتها، فلا يدفع من يفتح لوحة المعلومات ثمن صفحة التقارير.
ولهذا كُتب مولّد QR في المشروع بدل مكتبة: أصغر من أي بديل، ولا يُحمَّل أصلًا
إلا في مسار الطباعة.

### قاعدتان في كتابة سياسات RLS

**١) لُفّ نداء الدالة بـ`(select …)`.** `(select public.has_permission(…))`
يُقيَّم مرة واحدة لكل عبارة (InitPlan) لا مرة لكل صفّ. الفرق بين الشكلين هو
الفرق بين استعلامٍ يعود في ميلي ثانية وآخر يعود في ثوانٍ على جدولٍ كبير.
اختبارٌ ساكن يفحص أن كل سياسة تلتزم بذلك.

**٢) لا منطق صلاحيات مكرّر خارج RLS.** التكرار لا يبطئ فحسب — بل ينحرف مع
الوقت، والانحراف في التقارير لا يُرى لأنها تعرض أرقامًا لا صفوفًا.

### ⚠️ الخط يُجلب من Google وقت التشغيل

`index.html` يحمّل «IBM Plex Sans Arabic» من `fonts.googleapis.com`. وهذا:

1. **يسقط في الشبكات المُقيّدة.** كثير من شبكات الجهات الحكومية تحجب النطاقات
   الخارجية، فيتغيّر شكل التطبيق كلّه — وغالبًا في أسوأ لحظة: أثناء العرض.
2. **يُبلّغ Google بكل فتحة صفحة.** لا يحمل بيانات المراسلات، لكنه اتصال خارجي
   يقع في نظامٍ بقية اتصالاته محصورة.

البدائل في `tailwind.config.js` عربية صريحة (Noto، Segoe UI، Tahoma) فيبقى
النص مقروءًا عند الحجب — لكن الشكل يتغيّر.

**الحل الجذري: استضافة الخط ذاتيًّا.** الخط برخصة OFL تسمح بذلك:

1. نزّل ملفات `woff2` للأوزان ٤٠٠ و٥٠٠ و٦٠٠ و٧٠٠.
2. ضعها في `public/fonts/` وأضف `@font-face` في `src/index.css` مع
   `font-display: swap`.
3. احذف وسوم `<link>` من `index.html`.
4. **وضيّق سياسة الأمان بعدها**: احذف `https://fonts.googleapis.com` من
   `style-src` و`https://fonts.gstatic.com` من `font-src` في `netlify.toml`.
   نطاقٌ مسموح ولا يُستعمل سطحُ هجومٍ بلا مقابل.

⚠️ نفّذ هذا **قبل** أي عرض على شبكة لا تتحكّم فيها.

### ما لم يُقس بعد — بصراحة

لم يُقس شيء من هذا على بيانات إنتاج حقيقية: المشروع لم يُشغَّل بعد بحجمٍ
مؤسسي. الأرقام أعلاه أحجام حزم وقرارات فهرسة، لا قياسات أداء.

**القياس الحقيقي يبدأ بعد أول شهر تشغيل**، من
Supabase → Advisors → Query Performance. أنماط الاستعلام الفعلية هي التي
تُظهر الفهرس الناقص — لا التخمين قبلها.

نقاط يُرجَّح أن تحتاج مراجعة عند النمو:

- `audit_log` ينمو بلا حدّ. تقسيمه بالتاريخ (partitioning) أو أرشفته قرارٌ
  يُتخذ حين يصير حجمه مؤثرًا، لا قبله.
- تقارير المدى الزمني الطويل على مؤسسة كبيرة قد تحتاج `materialized view`
  تُحدَّث دوريًّا. لم يُبنَ ذلك: تعقيدٌ بلا حاجةٍ مُثبَتة.
- `search_correspondence` محدودة بـ‎٢٠٠ صفّ في الاستدعاء الواحد. الترقيم
  (pagination) يُضاف حين تُظهر الحاجة أن الحدّ يُبلَغ فعلًا.

## اختبار التعافي

خطة تعافٍ غير مُختبَرة ليست خطة.

**مرة كل ربع سنة على الأقل**: استعد نسخة إلى مشروع Supabase منفصل، طبّق
الهجرات، شغّل اختبارات التكامل عليه:

```bash
QALAM_TEST_DATABASE_URL="postgres://…/restored" npm run test
```

واقرأ نتيجة التمرين بصدق: إن لم تُستعد المرفقات، فقد أثبت التمرين ما يقوله
هذا المستند — لا أنه فشل.
